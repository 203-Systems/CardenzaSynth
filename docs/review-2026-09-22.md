# ComputeCardOS 完整性审查 — 2026-09-22

> 本文件保留修改前的审查快照。后续修复、测试结果和仍未完成的部分见 [实现与验收记录](implementation-2026-09-22.md)，页面与设计参考见 [UI 清单](ui-inventory.html)。

## 范围与结论

审查当前工作区，包括未提交和未跟踪的 Sequencer 实现；基线 HEAD 为 `146f90c`。未修改产品代码。核对了旧任务 **更新键盘模式与布局**（`019e1bb0-b032-7842-9639-58c2f03b5330`），该任务的可读取记录主要覆盖键盘布局及之后的 Xtensa 排序编译修复，不代表整个项目已完成。

当前具备设备抽象、四音轨、AMY 工厂音色、键盘布局、Sampler 文件流程及 Sequencer 编辑模型。主要缺口在于：音色编辑没有完整驱动 DSP，Sequencer 播放入口未接通，项目和音色缺少持久化，采样和播放的实时性与异常处理未收口。

以下“代码确认”表示可以由现有控制流确定；性能、内存和并发问题均未做本轮实机复现。不能把既有编译记录、模拟器截图或静态检查当成硬件验收。

## 优先处理的问题

### 1. [P1 / 代码确认] 大多数音色参数只改变界面，不改变声音

- `Library/Synth/Core/Engines/Dx7/Dx7SynthEngine.cpp:97`：只允许 `global.transpose` 同步至运行时。Algorithm、Feedback、LFO、六个 Operator 的各项参数均被过滤。
- `Library/Synth/Core/Engines/Juno/JunoSynthEngine.cpp:59`：只允许 `dco.range`、`vcf.cutoff`、`vcf.resonance`。PWM、Sub、Noise、Saw、ADSR、VCA、LFO、Chorus、HPF 均不生效。
- `Library/Synth/Audio/Amy/SynthAudioRuntimeAmy.cpp:625`：运行时同样只处理以上 DX7/Juno 参数，单纯删除过滤也不够。
- 两类工厂 Preset 均以空参数表注册，`PagedSynthEngine.cpp:266` 随后用通用默认值填充 UI；实际声音由工厂 patch 加载。因此界面数值也不一定是当前音色真实值。

**需要补齐：** 工厂 patch 到编辑模型的解码、参数到 DSP 的映射及更新。尚不支持的参数应禁用或隐藏。

**验收：** 切换不同工厂音色，界面能显示对应参数；逐类改变参数有可验证的音频变化；编辑后保存并重载，声音保持一致。

### 2. [P1 / 代码确认] Sequencer 的播放与停止没有 UI 触发路径

- `Applications/Synth/UI/SynthUiModel.cpp:1367` 给 Home 第三、第四个右侧按钮设置了 Stop/Play 图标和说明。
- 同文件 `:728` 的 Home 右侧按键分支只处理前两个 octave 按钮；后两个只记录按下状态。`:868` 的释放分支也只清除状态。
- `Applications/Synth/SynthApp.cpp:396` 有 `SequencerTogglePlayback` / `SequencerStop` 消费分支，但全项目搜索没有相应 `QueueCommand` 生产者。
- `ContextActionId` 中存在 Sequencer 枚举，但菜单构造和动作处理没有完成接线。

**影响：** 步进事件、长度、力度、微步、复制等编辑代码已经存在，但当前正常 UI 操作无法启动 Sequencer 播放。

**验收：** 从正常设备输入路径录入一步，按 Play 能听到，按 Stop 能停止且释放音符；模拟器和硬件走同一条输入路径。

### 3. [P1 / 代码确认] Project 没有保存；Preset 只有内存保存

- `Applications/Synth/UI/SynthUiModel.cpp:2930`：Project Save 仅执行 `SelectStatus("Project", "SAVED", ...)`；New/Load/Save As 也只更新文字。
- `Library/Synth/Core/PagedSynthEngine.cpp:279`：SavePreset 只更新实例中的 `presets_`。没有写文件，重新创建音源实例或重启会丢失自定义音色。
- `Device::Storage::ProjectDirectoryPath()` / `PresetDirectoryPath()` 已有目录接口，但没有对应项目/音色序列化与恢复流程。

**需要补齐：** 按 `docs/sequencer.md` 定义版本化 Project，保存四轨引擎、音色参数、采样相对路径、键盘设置、Sequencer 数据和全局设置；Preset 独立存储。文件错误必须进入 UI，成功信息必须来自实际写入结果。

**验收：** 完成四轨作品后重启，加载可还原声音和序列；缺失采样、满卡、写入失败均有明确结果；覆盖失败不破坏原文件。

### 4. [P1 / 代码确认] 自定义 Preset 即使在本次运行内重载，也不能恢复原声音

- `PagedSynthEngine.cpp:281` / `:438` 为 Save As 创建 `user.N`，保存的只有 UI 参数，没有工厂基础 patch 身份或完整 DSP patch。
- `Library/Synth/Audio/Amy/SynthAudioRuntimeAmy.cpp:303` / `:314` 对未知 ID 分别回退至 DX7 patch 138 / Juno patch 32。
- DX7/Juno 的 `ShouldSyncParameterOnPresetLoad()` 都返回 false，因此保存的参数也不会恢复到 DSP。

**复现路径：** 选择一个不同于回退 patch 的工厂音色 → Save As → 切换音色 → 加载刚保存的 `user.N`。UI 名称恢复，但 DSP 加载回退 patch。

**需要补齐：** 保存可完整重建声音的数据。仅增加 SD 文件写入无法修复这一项。

### 5. [P1 / 代码确认] WAV 导入缺少长度和内存边界校验

- `Applications/Synth/Runtime/Sampler/SamplerManager.cpp:213`：先 `frames.resize(chunkSize / 2)`，再读取 `chunkSize` 字节。奇数 data 长度会向按整数帧分配的缓冲区多写一个字节。
- `:217` 把 EOF 当作读取成功，截断 WAV 可能被接受，未读到的尾部也被当作音频。
- 分配前没有检查文件剩余长度、格式合法性或最大采样容量，畸形/过大文件可触发巨大分配。

**需要补齐：** 验证 RIFF/chunk 边界、fmt 最小长度、PCM frame 对齐、真实读取字节数和容量上限，成功解析后再替换当前 sample。

**验收：** 奇数 data、截断文件、超大声明长度、错误格式均安全拒绝，原 sample 保持可播放。

### 6. [P1 / 静态风险] 录音采集与缓冲容量不匹配，内存预算也没有闭合

- `SamplerManager.cpp:374` / `:822`：只有主界面 Tick 会 PumpInput，每次最多读取 512 帧，没有独立录音 worker 或持续排空机制。
- `Devices/ComputeCard/computecard/mic/mic.cpp:18`：44.1 kHz，4 个 DMA descriptor × 64 帧，总容量约 5.8 ms。
- `Devices/ComputeCard/app_main.cpp:11` 请求 16 ms 帧周期；当前 `sdkconfig` 的 `CONFIG_FREERTOS_HZ=100` 还会影响实际量化周期。界面刷新间隔及额外开销已长于这段 DMA 缓冲，没有采集溢出反馈。
- `SamplerManager.cpp:444` 一次预留 5 秒 mono16，即 441,000 字节；保存时产生裁剪副本和 currentFrames，交给音频时又在事件与 DSP 状态中复制。当前 `Devices/ComputeCard/sdkconfig:1061` 关闭 PSRAM，C++ exceptions 也关闭，未提供容量不足的恢复路径。
- `SynthAudioRuntimeAmy.cpp:681` 在音频渲染线程处理大向量复制，加载或预览 sample 会占用实时渲染时间。

**需要补齐：** 独立采集/缓冲，明确最大 sample 容量和总内存预算，避免录音/UI相互阻塞，减少完整 PCM 副本，确保分配失败可恢复。是否使用 PSRAM 须按实际板型决定。

**验收：** 实机同时演奏、录音、刷新 UI，导出的样本时长与外部输入一致且无丢块；记录最大连续可分配内存、峰值占用和音频 overrun。

### 7. [P1 / 代码确认，播放入口修复后可触发] Sequencer 到音源的最后一段仍依赖 UI 帧率

- `Applications/Synth/Runtime/Sequencer/SynthSequencer.cpp:693` 有独立时钟 worker。
- `Applications/Synth/SynthApp.cpp:935` 却只把 MIDI 放入音轨端口队列；`:140` 的主界面 Tick 才调用 `rack_.DispatchPendingMessages()`。
- `Library/Synth/Core/PagedSynthEngine.cpp:103` 每次最多取 24 条，再送至音频事件队列。MIDI 包没有携带精确播放期限。
- 读取/写入 WAV、目录扫描和显示刷新都在该 UI 路径周围，会把准时产生的音符延迟或合并成一批。
- `OS/Framework/Midi/MidiPort.cpp:81` 队列满时无条件丢最旧事件，可能丢 NoteOff，且始终返回成功。

**需要补齐：** 让音频/实时事件消费独立于 UI；明确时间戳或音频块边界的调度；队列溢出必须可观测并保护 NoteOff。

**验收：** 四轨播放期间打开菜单、加载 sample、保存文件；测音符间隔与微步偏移、队列峰值，确认无成批补发和挂音。

### 8. [P1 / 静态并发风险] Stop 与时钟发音可能重排，切引擎存在生命周期竞态

- `SynthSequencer.cpp:733` 在锁内生成 NoteOn 并登记 NoteOff，解锁后 `:774` 才发送。
- `:86` 的 Stop 可以在上述间隙清除播放状态并发送 NoteOff / CC120，随后旧批次 NoteOn 才发出。停止后可能仍响，且对应 NoteOff 已被清除。
- `SynthApp.cpp:942` 在时钟线程通过 `rack_.PortForTrack()` 解引用音源；主线程 `SynthRack.cpp:22` 可以同时替换/销毁该 `unique_ptr`，没有共同同步。
- `SynthSequencer.cpp:674` 的固件 StopClockWorker 只清标记，不等待任务退出；若未来销毁/切换应用，需要先处理任务和对象的生命周期。

**需要补齐：** 串行化 transport 和 MIDI 输出顺序，给旧播放批次失效机制；发送使用稳定的音轨路由，避免时钟线程访问可销毁引擎对象；退出时等待 worker 完成。

**验收：** 在 pulse 产生与发送之间插入可控停顿，执行 Stop，确认最后消息一定是释放而非 NoteOn；播放期间反复切换音源与退出应用。

### 9. [P2 / 代码确认] Sampler 的空槽、One Shot 和裁剪保存语义未收口

- `SynthAudioRuntimeAmy.cpp:520`：没有 PCM 时仍进入 procedural tone fallback。空槽/删掉 sample 后按键仍会合成声音。
- `:485`：采样 cursor 到末端后，无条件重置到 start；`:512` 的非 loop 分支只设置 releasing。下一帧仍从开头读，所以 One Shot 会在 release 期间重复采样。
- `SamplerManager.cpp:883` 保存时已物理裁剪，随后只重置 UI 的 trim 边界；音源的 `sample.start/end` 参数没有归零。`SynthApp.cpp:461` 下一次同步还会把旧比例套到裁剪后的数据上，造成二次裁剪。
- `filter.resonance`、`amp.pan` 虽有存储字段，但实际 Sampler 渲染未使用。当前音频桥还将 AMY 双声道混成单声道，输出目标应在产品约定中讲清楚。

**验收：** 空槽输出静音；用首尾明显不同的短样本验证 One Shot 不重复开头；裁剪保存前后的有效内容一致；对外暴露的参数有实际作用。

### 10. [P2 / 代码确认] 覆盖保存失败可能破坏已有 WAV

- `SamplerManager.cpp:237` 用 `std::ios::trunc` 直接写最终文件；`:888` 在确认覆盖后直接走这一流程。
- 现有文件会先被截断，满卡、掉电或写入失败没有恢复副本；返回值也未覆盖析构关闭时的失败。

**需要补齐：** 同目录临时文件、完整写入/关闭校验、与目标文件系统匹配的替换和恢复流程。不要仅凭桌面 rename 行为承诺 FAT 上的掉电原子性。

**验收：** 注入写入/关闭/替换失败，原 sample 仍可读取，新 sample 不显示保存成功。

## 建议实施顺序与完成门槛

1. **纠正用户可见的假成功，接通最小闭环。** Project 未实现前禁用保存并说明；接 Play/Stop；空 sample 静音；确认音色参数支持范围。门槛：每个可操作入口有真实结果或明确不可用状态。
2. **收口音频和采样可靠性。** 修复 WAV 边界、One Shot、二次裁剪、录音采集和内存复制；处理 Sequencer 实时消费、Stop 顺序与引擎生命周期。门槛：四轨、录音、文件操作并发时，无崩溃、丢块、挂音，时序有测量依据。
3. **完成声音编辑和恢复。** 工厂 patch 解码、参数映射、自定义 Preset 音色重建。门槛：保存前后音色一致，而非只有 UI 参数或名称一致。
4. **完成持久化。** Project/Preset 版本化文件、相对 sample 引用、可靠覆盖、错误恢复。门槛：重启后作品完整恢复。
5. **完善 Sequencer 日常操作。** BPM、Mute/Enable、Resume、设置入口；overdub/外部同步等按产品范围逐项加入。门槛：用户无需模拟器专用操作即可制作并恢复一段四轨作品。
6. **建立最小回归与硬件验收。** 覆盖 transport、保存重载、畸形 WAV、参数音频效果及并发停止；记录 firmware 与 simulator 各自结果。随后再做扩展功能和纯视觉润色。

无需先做新 UI 框架或全面拆分代码。现有分层已能承载这些补齐工作，优先把接口两端接通并建立可复查的结果。
