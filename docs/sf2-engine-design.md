# SoundFont（SF2）引擎设计

状态（2026-11-23）：第 9 节按建议执行（用户确认固件开源，并让继续）。P1 已完成（第 11 节）；P2 写完了，包括预算、后台读音色和 VELO（第 12 节）：主机上编译通过、测试通过（11-23），没有编过固件、没有上过板子。

一条轨道从卡上的 `.sf2` 文件里选一个音色来演奏。引擎自己渲染音（不经过 AMY），整数运算，按块渲染；采样先尽量放进 PSRAM，放不下的从卡上边读边播。

## 1. 约束（实测或读代码得到）

| 项 | 数值 | 来源 |
|---|---|---|
| 一块 | 256 帧，5.8 ms | `kAmyFramesPerBlock`，`audio timing` 的 budget |
| 重负载下音以外的开销 | 每块 1.3–3.8 ms | 2026-11-14 板上压力测试（`g_overheadMicros`） |
| AMY 一个音每块 | Juno 0.53–0.71 ms，DX7 0.39–0.60 ms（运行中学到的值） | 同上 |
| PSRAM | 开机后约 2.0 MB 可用 | 启动日志 |
| PSRAM 里已有的预留 | Pattern 256 KB；采样器给 Pattern 留 256 KB；Plaits 每个音约 26–30 KB；Vocal 声库至多 128 KB | `kPatternSlowReserveBytes`、`kSampleSlowReserveBytes`、其它分支 |
| 内部内存 | 当前主分支开机后约 65 KB 可用 | 启动日志（压力测试固件） |
| 卡 | 4 线 SDMMC，FAT 簇 16 KB，同时最多打开 5 个文件 | CardenzaHAL `storage.cpp`（只读依赖） |
| FAT 快速 seek | 现在没开；ESP-IDF 5.3.5 有 `CONFIG_FATFS_USE_FASTSEEK`，只对只读打开的文件有效 | `sdkconfig`、IDF Kconfig |
| 现有采样流 | 块 1024 帧；块放内部内存，全局至多 16 块（32 KB）；至多 8 个流、16 个读者、同时打开 2 个文件；块号 15 位（一个流至多约 67 MB 音频） | `Library/Synth/Audio/SampleStream.*` |

两个音色库的统计（只读预设数据，单声道、int16、立体声对只取一边）：

| | MuseScore_General（215 MB） | GeneralUser GS（32 MB） |
|---|---|---|
| 一个音色整段进内存，中位数 / 第 90 百分位 | 1558 KB / 6.2 MB | 199 KB / 2.4 MB |
| 512 KB 以内的音色 | 31% | 71% |
| 每个采样只常驻 4096 帧时，512 KB 以内的音色 | 98% | 98% |
| 同上，要从卡上读的采样 | 93% | 69% |
| 带循环的区域里，到循环结束超过 2 秒的 | 30% | 1% |

没有量过的：板子能同时撑几路读卡流。这个数决定大音色库能不能用，见第 8 节的 P0。

## 2. 范围

做：
- SF2 2.01–2.04，16 位采样。
- 按键和力度分区、叠层（一个键至多 2 层）、根音和调音、循环模式 0 / 1 / 3、音量包络、调制包络（到音高和滤波）、两个 LFO、低通滤波、互斥组、固定键和固定力度。
- 规范要求的默认行为里听得出来的那几条，写死在引擎里（第 5 节）。

不做（第一版）：
- 文件里的调制器（`pmod` / `imod`）、SF3（Vorbis）、24 位（`sm24`）、立体声、ROM 采样、混响和合唱发送的生成器。
- 代价：少数自己改了力度曲线或加了自定义调制的音色库，听起来会和参考实现有差别。

## 3. 结构

四块，前三块只有新文件，不碰共用代码：

| 模块 | 线程 | 做什么 |
|---|---|---|
| `Sf2File` | 载入线程 | 打开文件，记下九张表和采样块的位置，建音色目录 |
| `Sf2Program` | 载入线程 | 把一个音色展平成区域表，定每个采样放哪里，读进内存 |
| `Sf2Voice` | 渲染线程 | 一个音：整数内层循环，块级包络和 LFO |
| 接入 | 渲染线程和界面 | 引擎种类、音的预算、工程和界面 |

建议的目录：`Library/Synth/Core/Engines/SoundFont/`（引擎类和参数）、`Library/Synth/Audio/SoundFont/`（解析、展平、音）。

### 3.1 `Sf2File`：只记位置

- 打开时走一遍 RIFF：`INFO`、`sdta`（只记 `smpl` 的偏移和长度）、`pdta` 的九张表（各记偏移和条数）。不读音频。
- 音色目录：顺序读 `phdr`，每个音色留 6 字节（bank、program、序号），按 bank 和 program 排序，放 PSRAM。300 个音色约 1.8 KB。
- 音色名不常驻：浏览器只要屏幕上那几行，按行从文件读（和现有的长列表规则一致）。
- 所有读取走文件描述符加一个内部内存的小缓冲（2 KB），不用无缓冲的 `FILE`。
- 文件是不可信输入：每个偏移、条数、下标都先检查；条数设上限（音色 4096，一个音色的区域 512、采样 256）；超限报错，不截断后硬播。

### 3.2 `Sf2Program`：展平一个音色

选中音色时，在载入线程上做，结果是一个不可变对象，用完整体释放。

合并规则（SF2 规范）：
- 一个音由"音色区域 × 乐器区域"的一对产生，两边的按键范围和力度范围取交集，交集为空就没有这一对。
- 乐器级：本区域的值 → 没有就用乐器全局区域的值 → 再没有用默认值（覆盖关系）。
- 音色级：本区域的值 → 没有就用音色全局区域的值，**加到**乐器级的结果上。
- 音色级不允许的生成器（采样偏移、根音覆盖、循环模式、互斥组、固定键、固定力度）忽略。
- 循环点整理：越界的夹到采样范围内，起止颠倒的交换，循环短于 2 帧的当作不循环。

每个区域存成约 64 字节的定长记录（范围、采样下标、起止和循环点、模式、根音和调音、衰减、两条包络、两个 LFO、滤波、互斥组、固定键和力度），单位全部在这里换算好，渲染线程不做任何换算。400 个区域约 25 KB。

立体声对：输出是单声道，同一个键上互相链接的左右两个采样只留左边（内存和 CPU 都减半）。

### 3.3 采样放哪里

对音色用到的每个采样，算出它"需要的帧数"：带循环的到循环结束（模式 3 再加循环之后的尾巴），不带循环的到结尾，取用到它的所有区域里最长的。

两种放法：

| 放法 | 内存里有什么 | 音怎么读 |
|---|---|---|
| 整段 | 从起点到需要的结尾，外加 1 帧保护 | 只读内存；循环在内存里绕 |
| 头 + 流 | 开头 H 帧（默认 4096，最少 2048） | 先读头，过了头读采样流的块 |

保护帧：循环的采样在结尾多存一帧循环起点的值，不循环的多存一帧 0。内层循环插值时不用判断边界。

分配步骤（确定性的，同一个音色每次结果相同）：
1. 每个采样先给一个头。头的总和超过额度时把 H 降到 2048；还超就拒绝，提示 `FONT TOO BIG`。
2. 剩下的额度从"需要的帧数"最小的采样开始，依次升成整段，直到放不下。
3. 第一版没有流式（第 8 节 P2）：这时任何一个采样不能整段放下，就拒绝并提示需要多少 KB。

额度（建议值，见第 9 节决策 2）：
- 一条 SF2 轨至多 512 KB（区域表、头和整段采样合计）。
- SF2 不会让 PSRAM 的可用量低于 512 KB（Pattern 的 256 KB 预留，加上给其它引擎的余地）。后载入的轨道拿剩下的。
- 工程按 T1 到 T4 的顺序载入，所以同一个工程每次分到的额度相同。

### 3.4 采样流：在现有 `SampleStream` 上扩展

沿用现有的做法（按块号查的块缓存，渲染线程无锁读取，后台任务预读），不改成每个音一个环形缓冲。理由：按住的循环音，循环段的块读进缓存后就不再读卡；同一个采样的几个音共用块。

要改的地方：

| 现在 | 改成 | 为什么 |
|---|---|---|
| 一个流 = 一个 WAV 文件，块号 15 位 | 一个流 = 一个文件，块号 29 位（按文件的 2 KB 网格） | 215 MB 的文件有约 10 万块，15 位放不下；按文件网格对齐后每次读都是整扇区 |
| 块在内部内存，全局 16 块 | 块在 PSRAM，经一个内部内存的中转块（2 KB）读入再拷过去 | 卡的 DMA 只能读进内部内存，而内部内存只剩几十 KB；PSRAM 里可以放 64–128 块 |
| 预读"当前块和下一块" | 读者发布位置、步进、循环起止和是否已松键；预读量按音高算，快到循环结束时预读循环起点的块 | 高音读得快；循环跳转不能等卡 |
| 每帧调一次 `Read` | 一次取一块的指针，内层循环跑到块尾 | 每帧一次函数调用比读采样本身还贵 |
| 读者 16 个 | 加上 SF2 的音 | — |
| 没开快速 seek | 开 `CONFIG_FATFS_USE_FASTSEEK` | 几路流在同一个大文件里来回跳，不开的话往回 seek 要从头走簇链 |

规则：
- 卡来不及：这一小段保持上一个采样值（现有行为）；连续缺块超过一块的时间，这个音在一块内淡出，并计入统计。不直接掐。
- 流式区域限制最高音高（建议根音以上 2 个八度），超过的音只播常驻的头然后淡出。
- 同一个 `.sf2` 被几条轨道用时共用一个文件描述符。卡驱动一共只有 5 个文件位，采样流现在占 2 个。
- 块缓存只在有流式的音时存在，用完归还（和现在一样）。

上限是多少路要等 P0 量出来再定。在那之前，设计按"撑不住就淡出、不卡音频"来保证最坏情况。

## 4. `Sf2Voice`：一个音的渲染

每个音一次渲染一块（256 帧），内部按 64 帧一段更新控制量。全整数。

| 环节 | 做法 |
|---|---|
| 位置 | 32 位帧下标加 16 位小数；一段连续的读取里用一个 Q16.16 的相对量，一次加法前进 |
| 分段 | 先算"到块尾、段尾、循环结束或缓存块边界还有几帧"，这一段里的循环体不做任何判断 |
| 插值 | 线性：`a + (((b - a) * 小数15位) >> 15)` |
| 音量 | Q15 增益，在 64 帧内逐帧线性过渡到目标值 |
| 音量包络 | 起音在幅度上线性；保持之后的衰减和释放在分贝上线性（规范）；数值以厘分贝存，查表换成增益 |
| 起音中松键 | 把当前的线性幅度换算成等效的分贝值再进释放，不跳变 |
| 调制包络、LFO | 每 64 帧一步；LFO 是三角波，延迟后从 0 向上 |
| 音高 | 音分查表（一个八度 1200 项，再按八度移位）；没有调制时只在起音时算一次 |
| 滤波 | 两积分器状态变量低通，定点，64 位乘积；截止和共振查表；系数在 64 帧内线性过渡 |
| 滤波旁路 | 截止在 13000 音分以上、共振为 0、没有调制时整个跳过 |
| 输出 | 累加进这条轨道的 int32 缓冲；一块渲染完，整条轨道转一次 float 交给现有的轨道总线 |

表都放 flash（约 8 KB）：厘分贝到增益、音分到频率比、力度到衰减、滤波系数。渲染线程上没有 `pow`、没有浮点除法、不分配内存。

音数：
- 一条轨道 8 个音，一个键至多 2 层。
- 满了以后：先用空闲的，再抢最早松开的，再抢最早按下的（计入 stolen），和采样器相同。
- 同一个键在按住时再次触发：旧的那个快速释放。

估计的开销（没有量过）：不过滤波时每个音每块 40–60 微秒，过滤波时 80–100 微秒。作为对照，Juno 一个音每块约 600 微秒。

## 5. 行为规格

实现只依据这一节、公开的 SF2 2.04 规范和许可证宽松的代码（TinySoundFont、copych 的 ESP32 采样器，都是 MIT）。不打开 FluidSynth、FluidLite、TiMidity++、LinuxSampler、ESP8266Audio 的源码。

换算：
- 时间：秒 = 2^(timecents / 1200)；-32768 表示 0。延迟和保持至多 5000，起音、衰减、释放至多 8000，下限 -12000。
- 按键对保持和衰减时间的缩放：加上 (60 − 键号) × 生成器的值（timecents）。
- 频率：Hz = 8.176 × 2^(音分 / 1200)（LFO 频率、滤波截止都用这个）。
- 音高：音分 = 调音刻度 × (键 − 根音) + 100 × 粗调 + 细调 − 采样的音高修正；步进 = 2^(音分 / 1200) × 采样率 / 44100。调音刻度默认 100。
- 增益 = 10^(−厘分贝 / 200)。
- 滤波截止限制在 1500–13500 音分；共振以厘分贝给出，Q = 10^((厘分贝 / 10 − 3.01) / 20)，0 就是没有峰。
- 粗偏移一个单位是 32768 帧。

写死的默认行为：
- 力度到音量：衰减 = 400 × log10(127 / 力度) 厘分贝，也就是增益与力度的平方成正比。必须有，否则所有音色的力度响应都不对。
- 互斥组：同一条轨道上同组的音在新音触发时快速释放。踩镲开合靠它。
- 循环模式 3：按住时循环，松键后继续播到采样结尾。

跟随参考实现（FluidSynth）而偏离规范的两处，因为音色库都是在它上面试听的：
- 文件里的初始衰减乘以 0.4（乐器级和音色级都是）。
- 规范里"力度到滤波截止"的默认调制不做。

## 6. 接入

SF2 是"自己渲染音"的引擎，和采样器、Plaits、Vocal 同一类：在音频任务（核 1）上、AMY 那一块之后渲染，结果进现有的轨道总线和插入效果。

| 点 | 做法 |
|---|---|
| 引擎种类 | `SynthEngineKind::SoundFont`。编号在几个分支合并时统一定：现在 Braids、Plaits、Vocal 各自占了 5，Wave 用 8 |
| 渲染入口 | 用 Plaits 和 Vocal 分支引入的"自渲染轨道"入口（`RenderOwnTrackNoLock`）。两个分支现在各改了一遍同样的地方、判断函数名字不同，建议合并时收成一个接口，SF2 实现它，不再加第四种特例 |
| 预算 | 学习每个音的开销，从 AMY 的可用时间里扣掉；超了只淡出本轨的音，先松开的尾巴，再最轻的按住音（Plaits 分支的做法）。不像采样器和 Vocal 那样算进"其它开销" |
| 音符 | 走事件队列（`NoteOn` / `NoteOff` / `AllNotesOff`）；按住的音经 `PublishHeldNotesNoLock` 交给 `EndOrphanNotes` |
| 换音色 | 载入线程建好 `Sf2Program`，经一个事件交给渲染线程；渲染线程在块边界换指针，旧的音先淡出一块，旧对象交回载入线程释放 |
| 载入在哪跑 | 浏览时在设备的后台任务上跑，界面显示 LOADING，这条轨道在载入完之前不出声；选择变了就取消。载入工程时在 `ReplaceSession` 里同步做，那时输出本来就保持静音 |
| 工程 | 字体文件名放 `TRACK` 行的文件名字段（采样器和 Vocal 已经在用）；bank 和 program 是引擎参数。和其它新引擎一起进格式 8 |
| 文件不在 | 和采样一样：自动保存恢复时记下名字、轨道不出声、继续；按名字载入工程时失败并提示 `FONT MISSING` |
| 存放 | 卡上新增 `CardenzaSynth/SoundFonts/*.sf2`，经 `synth::storage` 取得；`docs/app-storage-protocol.md` 同步更新 |
| 电平 | 引擎一个固定增益，按"GM 钢琴、力度 100 约等于 Juno 的电平"校一次；不做每个音色的电平表（字体是用户的） |

界面（INSTR，按信号顺序）：
- VOICE：字体名和音色名。ADD / SUB 按 bank 和 program 的顺序换音色；ENTER 打开音色浏览（可搜索）；FN 菜单里 FONT 选 `.sf2` 文件。
- CHORD、ARP：和其它旋律引擎一样。
- TONE：在音色自己的值上加偏移：CUTOFF、RESO、ATTACK、RELEASE、TUNE、FINE、LEVEL、VELO（力度灵敏度）。
- FX：和其它引擎一样。

引擎参数约 10 个加轨道效果，用 `ReserveParameters` 声明数量。新参数格加进 `CellParameter` / `SetCellParameter`。

第一版里 bank 128 的鼓组当作键盘轨来弹，没有鼓机视图（见决策 5）。

## 7. 测试

- 主机：测试自己生成小的 SF2 文件（正弦和噪声的多重采样），仓库里不放第三方音色库。
  - 解析：全局区域、范围交集、覆盖与相加、循环点整理、各种越界和截断的文件（不崩溃、有界时间内返回）。
  - 渲染：整数的音对一个双精度的参考实现（测试里按第 5 节自己写的），信噪比不低于 60 dB；包络各段的时间；循环接缝。
  - `TestNoStuckNotes` 加上 SF2 轨道。
- 板上：压力测试加场景。
  - `sf2-ram`：四轨各 8 个音，全在内存里。
  - `sf2-stream-4` / `-8` / `-16`：这么多路流式的音同时响。
  - 测试用的字体由压力测试自己写到卡上。
- 板上的结果才算数：开销、断音、淡出的音数。

## 8. 分期

| 期 | 内容 | 需要板子 | 碰共用代码 |
|---|---|---|---|
| P0 | 量读卡流的路数：四条采样器轨各 4 个音播长采样（现有引擎就能做），开和不开快速 seek 各量一次 | 要 | 只有压力测试和 `sdkconfig.defaults` |
| P1 | `Sf2File`、`Sf2Program`、`Sf2Voice` 和主机测试 | 不要 | 不碰 |
| P2 | 接入：引擎种类、渲染入口、预算、界面、工程；只支持整段进内存的音色，放不下的拒绝 | 要 | 碰，排在 Plaits / Vocal 合并之后 |
| P3 | 采样流的扩展，头 + 流，循环的预读 | 要 | 碰 `SampleStream` |
| P4 | 用户音色（字体 + 音色 + TONE）、鼓组的处理、把音以外的开销降下来 | 要 | 碰 |

P1 现在就能开始，和其它分支不冲突。它需要编主机测试，按项目规则要你先同意。

P2 做完时，紧凑的音色库（GeneralUser GS 这一类）大约七成音色能用；大音色库要等 P3。

和这份设计相关、但不属于它的一项：把"每个音逐帧转 float 再加锁进总线"改成每条轨道先用整数累加。它对 AMY 的音同样有用，适合在几个引擎分支合并之后单独做。

## 11. P1 的实现

文件都在 `Library/Synth/Audio/SoundFont/`，测试是 `tests/sf2_test.cpp`（`CardenzaSoundFontTests`）：

| 文件 | 内容 |
|---|---|
| `Sf2Format.h` | 生成器编号、九张表的记录大小、上限、状态码 |
| `Sf2Source.h` | 字节来源接口（卡上的文件、测试里的内存）和带窗口的读取器 |
| `Sf2File.*` | 第 3.1 节：走一遍 RIFF，记位置，音色按 bank / program 排序，名字按需从文件读 |
| `Sf2Program.*` | 第 3.2 节：合并、取交集、整理循环点、立体声只留左边、按额度读采样；超额度返回 `TooBig` 和需要的字节数 |
| `Sf2Tables.*`、`Sf2Tables.inc` | 换算表，由 `tools/audio/gen_sf2_tables.py` 生成（约 11 KB 代码和表） |
| `Sf2Voice.*` | 第 4 节：整数的一个音 |
| `Sf2Track.*` | 一条轨道 8 个音：分配、抢音、互斥组、同键重按 |

测试（89 项，全部通过）：
- 换算表对公式；文件解析；合并规则（覆盖、相加、交集、音色级禁用的生成器被忽略）；循环点整理；立体声对。
- 整数的音对同一算法的双精度模型：循环接缝和插值信噪比高于 60 dB；滤波器与教科书状态变量低通的误差小于输出的 1 个单位；滤波器的频率响应与公式相差不到 0.3 dB。
- 包络各段的时间和电平、力度曲线、起音中松键不跳变、颤音和调制包络到音高、循环模式 1 和 3、抢音不爆音、互斥组。
- 损坏的文件：每一种截断，以及 4000 个随机改坏的文件（3571 个能打开，20430 个音色建起来并播放过），在地址和未定义行为检查下没有一次越界或崩溃。

还验证了：项目的 ctest 能编能跑；架构检查通过；用 ESP32-S3 的编译器编过这些文件（没有链进固件，没有上板）：每帧的循环里没有任何函数调用，控制步每 64 帧调几次查表函数，64 位除法只在音开始时出现。

实现中改过的设计：
- 定点运算一律四舍五入，不截断。滤波器里截断的误差会被反馈放大成直流偏移（放大约 k/g 倍，低截止时几百倍）。
- ESP32 上 `int32_t` 是 `long`，`std::min(int32_t, 0)` 这类混用类型的写法主机能编、固件编不过，所以字面量都写成 `std::int32_t{0}`。
- 每帧的计算写成 lambda 时 GCC 没有内联，现在强制内联。
- 16.16 的步进在采样被降好几个八度播放时变粗：音高误差在 0.03 音分加一个步进单位以内。

P1 没有碰共用代码，只在 `tests/CMakeLists.txt` 里加了一个测试目标。下一步是 P0（量读卡流的路数，需要板子）和 P2（接入，排在 Plaits / Vocal 合并之后）。

## 10. 没有核实的

- 每个音的开销是估算。
- 快速 seek 在碎片很多的大文件上够不够：IDF 默认的簇链表只有 64 个字（约 31 段），不够时会退回普通 seek。要在板上看。
- 卡驱动的 5 个文件位在 CardenzaHAL 里，要加得改上游。
- 载入一个 512 KB 的音色要多久：估计 0.3–1 秒，取决于卡。
- 其它分支的细节来自阅读它们未提交的工作区，合并前可能还会变。

## 12. P2 的实现

分支 `claude/sf2-engine-p2`，从合并了全部引擎的 `claude/synth-integration` 分出。SoundFont 是第 10 种引擎（`SynthEngineKind::SoundFont = 10`），引擎选择里排最后（SFONT）。界面和操作写在 `AGENT.md` 的「SoundFont」一节，文件和工程写在 `docs/app-storage-protocol.md`。

| 位置 | 内容 |
|---|---|
| `Library/Synth/Core/Engines/SoundFont/` | 引擎：文件里的音色就是它的出厂音色（`sf.<bank>.<program>`，没有音色时是 `sf.none`），参数是 TONE 页的八项（`SoundFontParameters.h`）和轨道效果。它只通过 `soundfont::Font` 接口拿音色，自己不碰卡；有后台可用时选的音色在后台读，原来的音色先继续响 |
| `Applications/Synth/Runtime/SoundFont/` | 卡上的文件：列出 `SoundFonts/*.sf2`，打开一个文件（只在读的时候开着，经过 4 KB 的内部内存块），把一个音色读进内存，把失败的原因变成给用户看的字；后台读音色（`Device::Background`，每条轨一个请求，新的替换没开始的旧的，按票号取结果） |
| `Library/Synth/Audio/Amy/SynthAudioRuntimeAmy.cpp` | 渲染：和采样器、Plaits、Vocal 一样是"自己渲染的轨道"，8 个音先加进一条整数总线，再走同一套增益斜坡、插入效果和发送。换音色是一条排队的事件：先让这条轨的音淡出，音停了再换，期间这条轨的事件在队列里等。预算和 Plaits 合在一起算（"实测的轨道"）。渲染线程放手的音色经一个单向环交回界面线程释放 |
| `Applications/Synth/GrooveApp.*`、`Runtime/ProjectStorage.cpp` | 工程：TRACK 行最后一项是文件名；载入时先开文件再恢复音色（同步读）；几条轨共用一个打开的文件；自动保存恢复时文件不在，等卡回来再接上；后台读失败时弹提示 |
| `Applications/Synth/UI/Groove/` | 引擎选择的第十格、VOICE 页的 FONT 和 LOADING、文件列表、TONE 页、FN 菜单的 FONT |
| `Applications/Synth/StressSoundFont.h`、`StressTest.cpp` | 压力测试写到卡上的音色库（两个音色，每个音两层，滤波在动）和 `sf2` 场景 |

### 预算（第 6 节）

SF2 和 Plaits 一样只在音频核上渲染、开销不按模型估：每条轨实测一个声部一块要多少微秒（`g_measuredVoiceMicros`，原来的 `g_plaitsVoiceMicros` 改了名，两种轨共用），没渲染过一整块之前是 0，不算进预算。AMY 的音和这些"实测的轨道"分音频核的时间，后者至少有块长的 35%（`kMeasuredFloorMicros`）；超了，声部最多的那条实测轨收掉自己的一个音：先是最轻的已松开的尾音，再是最轻的按住的音，最后一个音留着（`sf2::Track::FadeVoice`，四个控制步、一个块内淡出）。`RenderLoad` 的保险在 AMY 轨和实测轨里挑声部最多的那条。这一套只在板上起作用（`ESP_PLATFORM`），主机上测得到的只有 `FadeVoice` 选哪个音、淡得干不干净。

### 后台读音色（第 6 节"载入在哪跑"）

用户选音色（VOICE 的 ADD / SUB、音色列表、换文件、新的 SoundFont 轨）时：引擎先向文件要一个后台请求（`Font::LoadLater`，拿到票号），再把状态换成新音色（名字马上变），原来的音色继续响，VOICE 写 LOADING。后台任务（优先级在界面之下，6 KB 栈）读完把结果放在这条轨的格子里；界面线程每帧（`DispatchPendingMessages`）按票号取：成功就交给音频；失败就恢复选之前的状态（这期间改的 TONE 一起回去），并通过 `TakeLoadFailure` → `GrooveApp::CheckSoundFontLoads` → 底部提示说原因。读的时候又选了别的音色，请求被替换；状态变成别的音色（选回正在响的、载入工程、恢复），没读完的作废（`OnRuntimeSynced`）。轨道换成别的引擎或引擎销毁时请求取消，已经读好的音色在后台任务或界面线程上释放。

和设计不同：设计说"这条轨道在载入完之前不出声"，现在是原来的音色继续响到新的就位，换得快时（按住 ADD 连发）声音不断。载入工程、恢复自动保存时仍然同步读，`ReplaceSession` 返回时一切就位。模拟器上没有后台任务，`LoadLater` 返回 0，一律同步读；主机测试用 `DeferSoundFontLoadsForTests` 把请求留着、自己调 `RunDeferredSoundFontLoads`，走的是同一条后台路径。

### 音色在哪个线程释放

一个音色是一百多块堆内存（每个采样一块）。现在引擎换音色时直接放手；音频线程自己持有的引用（正在响的、等着换上的、事件里带着的）放手时进一个 16 格的单向环（`LetGoOfProgramNoLock`，生产者都在渲染锁下，消费者是界面线程），`SynthRack::DispatchPendingMessages` 每帧调 `audio::CollectSoundFontPrograms` 在界面线程上释放。环满了才在渲染线程上释放（不该发生）。之前的做法（引擎留着旧音色直到引用计数降到 1）在轨道换成别的引擎时会让最后一个引用落在渲染线程上。

### 换音色时来的音

原来换音色那一小段（旧音淡出一个控制步，到下一块开头才换上）里来的音被丢掉。现在这条轨的事件在队列里等（`DrainPendingEvents`），换上后照常弹：每块渲染开头先完成等着的换音色、再处理事件，所以等着的音在下一块就弹（11-23 前顺序反了，要多等一块）。等的事件不算"还有活要干"，所以 `WarmUp` / `ResumeEffects` 的循环不会因为它空转。同一个音色再发一次（引擎因为别的原因同步）什么都不变，正在响的音不被切断。

### 和设计不一样的其它地方

- **TONE 是八项**：CUTOFF、RESO、ATTACK、RELEASE、TUNE、FINE、LEVEL、VELO，都是加在音色自己的数值上的偏移。VELO（`amp.velocity`，0–127，默认 127）按比例缩小力度带来的衰减：127 是音色原样，0 每个音都和最重的一样响；力度落在哪个区间（选哪层采样）不变。换文件时保留，换音色时回到默认。
- **工程里音色是预设编号，不是参数，也没有新格式**。bank 和 program 写成这条轨的预设 `sf.<bank>.<program>`，仍是格式 7；旧固件遇到种类 10 的轨道会拒绝整个工程，和别的新引擎一样。
- **电平没有校**。现在直接用采样器的增益（`kSamplerVoiceGain`），没有按「GM 钢琴力度 100 约等于 Juno」校过，要在板上听了再定。
- **用户音色没有测**。引擎走的是通用的音色保存（`Presets/SoundFont/user.ccpreset`），但一个用户音色只记得音色编号，不记得是哪个文件：换了文件它指向的就是另一个声音。按第 8 节这是 P4 的事，现在先不要依赖它。
