# Projects and storage

A **project** stores an entire song: all four tracks' engines and presets, patterns, song arrangement, mixer levels/mute/solo/SEQ states, track and master effects, BPM and swing, keyboard settings, and per-track chord and arpeggiator settings. Projects are stored on the SD card and managed from <Scene name="SETUP" /> <Page name="PROJECT" /> and <Page name="FILES" />. Cardenza also autosaves your active working session to the card (see [Session autosave](#project-session)). An SD card is required to store any data; without one, nothing persists across power cycles.

| Saved in a project | Not saved in a project |
|---|---|
| Engines, presets, sample references (by filename), patterns, song arrangement, mixer (levels, mute, solo, SEQ), track and master effects, BPM, swing, keyboard (KEYS), chords, and arpeggiators | `SELECT` (global app preference), device settings (volume, key LEDs, screen brightness, logging), LOOP/SONG mode, REC arm |

- Unsaved edits display `UNSAVED` next to the project name on PROJECT and on the SAVE tile in the FN menu. Starting a NEW project or loading another file prompts for confirmation first (<Key k="OK" /> to discard changes, <Key k="ESC" /> to cancel).
- The FN menu on PROJECT and FILES provides **NEW**, **LOAD**, and **SAVE AS** (see [PROJECT](./setup.mdx#setup-project) and [FILES](./setup.mdx#setup-files)).
- **NEW** initializes the four default tracks (<Track n="1" /> <Track n="2" /> <Track n="3" /> <Track n="4" />) with default keyboard settings (C major, chords off, arpeggiators off).
- Possible save errors (shown at the bottom of the screen): `NO SD CARD` (booted without a card), `SD CARD ERROR` (write failure), `SAVE SAMPLE FIRST` (unsaved mic recording pending), or `NO MEMORY`. Possible load errors: `INVALID PROJECT`, `SAMPLE MISSING` (referenced sample not found in `Samples/`), or `NO MEMORY`.
- Projects are plain-text `.ccproj` files using format v7. Formats v1–v6 load cleanly (files older than v6 do not include keyboard, chord, or arpeggiator data and keep your current settings). Firmware 0.1.0 only reads formats v1–v6 and cannot open v7 projects. Because projects reference samples by filename, renaming or deleting a sample affects every project using it.
- Saves write atomically to a temporary file before replacing the target, preventing corruption if power cuts out mid-save.

## Session autosave {#project-session}

When an SD card is installed, you can power off or unplug Cardenza at any time. Your working session is automatically saved in the background and restored on the next boot.

- Session autosave preserves everything a project stores, plus the active project name and whether it has `UNSAVED` edits (so loading another project still warns you). On boot, Cardenza restores onto T1.
- Autosave writes 1.5 seconds after you stop pressing keys (with no keys held), whether playing or stopped. During continuous input or card-streamed sample playback, it waits at most 60 seconds. Writes happen in the background without interrupting audio or display, and no-op keypresses do not trigger writes. Switching to another app flushes the session immediately.
- Autosave is temporary session state, not a named backup. Always press <Key k="FN+S" /> to save versions you want to keep before loading or starting a new project.
- If a write fails, the screen shows `AUTOSAVE FAILED: SD CARD ERROR` (or `NO SD CARD` if the card was removed) and keeps retrying until the card responds again.
- Unsaved sample recordings are stored in `Session/take-<track>.wav` and reload on restart (`UNSAVED TAKE IS BACK`). Any missing sample referenced by the session loads automatically once the card is readable again.
- If the device fails to boot three times in a row, the next startup skips session restoration once as a safety fallback.
- Session autosave does not preserve retrospective capture takes or transport playback state. Without an SD card, nothing is preserved (see [No card or card errors](#storage-card)).

:::tip

Device and app settings (SELECT, volume, key LEDs, screen brightness, logging) save automatically to the SD card about one second after you change them.

:::

## Folders on the SD card {#storage-layout}

All Cardenza Synth files live inside a single top-level `CardenzaSynth` directory on the SD card:

```text
<SD card>/CardenzaSynth/
  Settings/system.cfg      device settings (volume, key LEDs, screen, log)
  Settings/synth.cfg       synth preferences (SELECT)
  Projects/                saved projects (.ccproj)
  Presets/<engine>/        user presets
  Samples/                 WAV samples shared across all apps
  Session/                 autosaved working state and unsaved mic takes
  Logs/                    diagnostic logs (log.txt)
  Apps/<Author>/<Name>/    per-app storage for other firmware apps
```

- This directory layout matches release 0.1.0, so existing projects, presets, and samples work in place.
- Legacy paths from early dev builds (`Cardenza/`, or singular `Project`/`Preset`/`Sample` folders) are ignored. To use files from those folders, copy them into the paths above on a computer (the file formats are identical).
- Each app writes only to its own folder and the shared `Samples/` directory.

## Settings files {#storage-settings}

The `.cfg` files in `Settings/` are plain-text `key=value` files that you can inspect or edit on a computer:

```text
# Cardenza settings: Cardenza/Synth (storage protocol 2)
keys.select=1
```

The parser ignores malformed lines and preserves unknown keys, so newer and older firmware versions can share a card safely. When saving changes, Cardenza re-reads the file first and updates only the keys changed on the device, preserving manual edits made on a computer.

<Keywords k="settings file, config, cfg, text file, 设置文件" />

## Diagnostic logs {#storage-log}

When **LOG** is enabled on <Scene name="SETUP" /> <Page name="SYSTEM" /> (default ON) and an SD card is present, Cardenza logs startup info, firmware version, file loads/saves, errors, and crash reports to `CardenzaSynth/Logs/log.txt`. Once the file exceeds 512 KB, it rotates to `log.1.txt` and starts a new `log.txt`.

If you run into a crash, stuck audio, or save error, attach both log files with a short bug report. Setting **LOG** to OFF disables log writes completely.

## No card or card errors {#storage-card}

  <Caption>SD card status readout on SETUP SYSTEM.</Caption>

Cardenza checks for an SD card once at startup:

- **Booted without a card**: after the boot animation, a prompt warns `NO SD CARD, NOTHING WILL BE SAVED, INSERT A CARD AND RESTART TO SAVE` (dismiss with <Key k="OK" /> or <Key k="ESC" />). You can still play and tweak settings, but Cardenza will not mount a card inserted mid-session: nothing saves on power-off, saving reports `NO SD CARD`, FILES stays empty, and interactive USB lessons cannot start. Insert an SD card and restart.
- **Card stops responding mid-session**: failed operations display `SD CARD ERROR` while Cardenza retries detection. Settings and session autosaves flush automatically once the card responds again.
- Check current card status anytime on <Scene name="SETUP" /> <Page name="SYSTEM" /> (`SD CARD READY` or `NOT FOUND`).
